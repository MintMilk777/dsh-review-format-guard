# 技术实现与复核入口

[English](TECHNICAL.en.md)

[首页](../README-zh-CN.md) · [安装](../INSTALL.md) · [兼容性](../COMPATIBILITY.md)

这是独立的 DSH 插件，通过正式的 `llm/stream` 接口代理内置自动审查的模型请求。它不替换内置组件、不修改审查政策、不改变服务地址，也不执行工具。

## 做什么

- 默认不按服务或模型名称限制；这不表示已验证所有服务、模型或多模态包装。仅接管与已核对的旧版四栏目协议或 0.2.2-rc.1 多消息协议的审查政策指纹及请求结构均匹配的请求；不按商家或模型名称判断。普通对话、带工具的模型请求、第三方审批、标题生成和未知版本的审查均直接透传。
- 可选的 `providerIds` 是服务入口限制名单：默认空数组表示覆盖所有原生审查入口；设置名称后仅处理指定入口。模型名称始终不设白名单。无需手动编辑服务配置即可使用默认行为。
- 保留原系统提示词和全部待审数据，旧协议在数据末尾重申政策；多消息协议在第一条环境消息中说明记录边界并重申同一政策，明确最后一条工具调用已经是待审动作，无需等待新消息。即使传输层合并相邻 user 消息，后续 JSON 记录及其来源权限仍须分别理解；它们的顺序和原文保持不变，待审动作仍在最后。用于减少把待审调用误当成历史或把审查误当成对话续写的情况，不执行待审动作。
- 随流检查内容块结构与一致性，确认失败立即结束该次尝试并保留安全原因。成功结果仍须收完整条流，检查结束状态、内容一致性与结论后，再交还内置审查；合并可改变事件分段，不删减有效文字。
- 每段内容收到时保存独立副本，防止底层重复使用可变对象时覆盖先前收到的结论。
- 完整校验后，确认整块仅含空白的内容块会连同开始、增量和结束事件一起移除，避免原生解析器把它们计为额外正文。有效文字、思考、保留块的元数据及用量事件不变；发生规范化时清除失效的结束重放元数据。所有收到的事件仍先计入资源预算。
- 部分适配器会删掉思考过程最终快照的外围空白，却保留增量片段中的空白。仅当思考过程两份内容去掉外围空白后完全相同时，统一为已经收到的增量内容，同时丢弃失效的重放状态；实质内容不同仍然报错，最终结论仍要求增量和快照完全一致。
- 只处理明确包住整个结论的 Markdown JSON 代码框、外围空白、开头 BOM，以及整块为空白的内容块；不会从普通文字、DSML 工具调用、多个对象或推理过程里搜寻并拼凑结论。
- 缺失、冲突、重复字段、格式错误等会记录不含原文的错误码，然后重发同一份增强后的审查请求，默认最多重试两次（含首次共三次）。明确的合法拒绝通过完整流校验后交回 DSH，绝不为了取得允许而重试。
- 已知连接故障和部分临时服务错误有限重试。取消、卸载、认证失败、额度耗尽、输入过长、无效请求和未知异常不重试。每次有独立的等待期限与大小预算，详见下文。
- 成功结果仍由原来的 DSH 审查组件判断；全部尝试失败时交回失败，绝不增加工具放行例外。

## 安装和移除

使用 DSH 正常插件安装流程安装本目录或打包文件；桌面版本使用它自带的命令入口管理 `desktop` 配置。不要手工覆盖 `node_modules` 中的内置组件，不需要编辑服务配置、密钥或权限设置。

插件包自带的 `cordis.patch.yml` 只是 DSH 的标准插件挂载声明。正常安装时 DSH 会登记插件依赖和挂载信息；这不等于替换主程序或修改审批策略。

正常移除 `dsh-review-format-guard` 并重启即可退出此处理流程。移除它不会卸载内置自动审查，也不会替你切换权限模式。

## 局限

插件检查的是“接受的审查结果符合已核对的格式和字段规则”，不保证模型判断正确，也不能让有问题的上游每次都生成结论。DSML 工具调用全文不会被改写成授权结论；多次均不合格时仍会失败。

本版本不接入新的外部服务，不额外保存会话或请求原文。重试会增加上游调用次数、耗时和可能的费用。审查提示词变化后指纹不再匹配，插件会透传给内置审查，需重新核对兼容性。

源代码不含密钥，无运行时第三方依赖，没有安装后脚本。日志包含请求序号、尝试次数、是否规范化、安全错误码与毫秒耗时。失败尝试的简短历史会保留在后续成功日志和最终失败说明中；JSON 解析错误可附带固定的返回形态分类，流结构错误可附带缺少结论、出现动作块、快照冲突、输出截断等固定分类，不输出会话、结论、敏感信息或上游错误原文。

快速流会定期让出执行机会，使取消、卸载和期限回调能运行。每次读取结束即移除取消监听，避免等待回调积累。取消不等待卡住的读取或关闭操作；读取关闭方法、调用方法或异步关闭失败，都不覆盖主要错误。这不能抢占服务商代码单次同步执行的阻塞。

移除结论 JSON 围栏时保留后续片段的额外元数据，并清除修改文字的旧签名。仅修正思考空白时，不合并无需修改的结论片段，也不移除其签名。

## 等待与重试

三个期限均按单次尝试计算，以最早到期者为准：

| 选项 | 默认值 | 含义 |
|---|---|---|
| `timeoutMs` | `180000`（180 秒） | 从尝试开始到完整校验结束的固定总期限，不随内容续期 |
| `firstContentTimeoutMs` | `120000`（120 秒） | 等待首个非空白文字或思考内容 |
| `idleTimeoutMs` | `30000`（30 秒） | 首内容出现后，等待下一段有效内容；每次有效进展重置 |

有效进展包括非空白文字或思考增量，以及没有先前增量的首个非空白结束快照。`usage` 用量统计、纯空白、已收到增量后的结束快照和重复快照都不续期。思考内容能推进等待，但不能替代最终审查结论。完整校验后的缓冲结果回放不计入服务端空闲等待。

只有省略的选项使用默认值。显式设置的旧 `timeoutMs` 仍生效，例如 `60000` 仍把单次尝试限制在 60 秒，即使首内容期限为 120 秒。总期限始终不续期。

`retries` 默认 2，最多也只能为 2，含首次共最多三次尝试。每次重新计算期限；默认最坏约 9 分钟，再加 500 毫秒和 1000 毫秒的退避等待，并非整次请求最多 180 秒。首内容或空闲超时、不可重试错误可提前结束。缺失或冲突仍最多三次。遇到资源超限后，总尝试上限收为两次；若前两次是其他错误、第三次才首次超限，则直接结束，不再追加。`retries: 0` 仍只尝试一次，`retries: 1` 最多两次。合法拒绝通过完整校验后一次结束。不新增跨重试共享的总等待预算。

错误分类与是否重试见[排查说明](TROUBLESHOOTING.md#错误分类)。连接异常只依据源码列出的连接错误码识别，也检查其原因链；识别到取消时优先停止。仅凭 `fetch failed` 或消息里有“network”不能判定可重试。未知异常不盲目重试，日志只记录安全分类，不输出上游错误消息、地址或原因链原文。

## 流缓冲预算

与前一版主要依靠等待期限的处理相比，流中一旦确认失败，就结束本次尝试并保留安全分类原因，不再等流关闭或超时。成功结果仍须收完整条流并通过完整校验；仅出现看似合法的结论或正常结束标记，还不能提前交回。

只合并相邻、同类型且同一内容块编号（`index`）的纯文字或思考增量。“纯”指只有 `type`、`index`、`text` 三个字段；每组合并内容最多 4096 个 UTF-16 编码单元。合并保留思考文字，不会为了合并而丢弃额外元数据；带额外字段的事件单独保留。

以下预算各自按单次尝试计算，任一超限就结束该次尝试：

| 选项 | 默认值 | 计量范围 |
|---|---|---|
| `maxBytes` | `262144`（256 KiB） | 合并后保留事件的序列化体量，仍包含完整结束快照；单个收到的事件序列化后也不能超过此值 |
| `maxChunks` | `65536` | 合并前收到的全部原始事件数，包括思考和用量统计 |
| `maxContentBytes` | `262144`（256 KiB） | 有效正文与思考内容字节数；结束快照不重复计算已有增量内容 |
| `maxReplayBytes` | `262144`（256 KiB） | `replayState` 状态序列化后的累计字节数 |
| `maxBufferedChunks` | `8192` | 合并后实际保留的事件数 |
| `maxMemoryBytes` | `4194304`（4 MiB） | 对保留表示、内容副本与对象槽位的保守内存计量，并非 JavaScript 实际堆内存的精确测量或上限 |

原始事件数默认上限从 8192 增至 65536，实际缓冲事件数仍限 8192。显式配置的旧 `maxChunks: 8192` 仍生效。`maxBytes` 数值仍为 256 KiB，但累计口径改为合并后的表示，不能概括为所有大小上限都没变。合并只能减少部分分片开销，不能消除所有分片差异：即使最终文字很少，超过原始事件数上限仍会失败；完整快照与额外元数据也仍可能触及其他预算。

## 验证

`npm test` 可独立运行，无需本机安装 DSH、无需网络或密钥。包括格式、冲突、流一致性、有限重试、取消、卸载与模型无关的入口识别测试。测试使用带有原始 MIT 许可的 0.2.1-rc.3 政策、解析器快照和 0.2.2-rc.1 政策快照；它不进入安装包。

`npm run test:host` 在单独进程中使用本机 DSH 自带的真实 Cordis 和内置审查解析逻辑验证接入与撤载。它不修改 DSH 安装文件、用户配置或会话，也不调用远端模型。

设置 `DSH_EXECUTABLE` 与 `DSH_ARCHIVE` 可指定本机 DSH 程序和 app.asar 的位置。主机接入测试需要受支持的 DSH 安装，不能用快照测试替代。

模型无关表示相同的原生请求处理流程可以接入不同模型，不代表每个模型都已验证，也不能弥补模型自身的判断错误或上游拒绝服务。生图模型不适合作为文字审查模型。高风险样例必须仅作独立、虚构的审查请求，不绑定工具执行器。

- [lib/index.js](../lib/index.js)：监听器、重入、重试、取消与卸载。
- [lib/wait.js](../lib/wait.js)：单次总期限、首内容等待与空闲期限。
- [lib/failures.js](../lib/failures.js)：安全错误分类与重试判定。
- [lib/protocol.js](../lib/protocol.js)：政策指纹、请求结构与结论校验。
- [lib/stream.js](../lib/stream.js)：内容块副本、流中失败检测、完整校验与有限规范化。
- [lib/budget.js](../lib/budget.js)：相邻增量合并与单次资源计量。

默认选项通过 `apply(ctx, options)` 传入，本版本没有图形设置面板：

```json
{
  "enabled": true,
  "providerIds": [],
  "retries": 2,
  "timeoutMs": 180000,
  "firstContentTimeoutMs": 120000,
  "idleTimeoutMs": 30000,
  "retryDelayMs": 500,
  "maxBytes": 262144,
  "maxChunks": 65536,
  "maxContentBytes": 262144,
  "maxReplayBytes": 262144,
  "maxBufferedChunks": 8192,
  "maxMemoryBytes": 4194304
}
```

生产插件不读取 app.asar，可选宿主验证脚本才读取安装包。政策指纹必须匹配已核对的旧版政策或 0.2.2-rc.1 政策。多消息协议只在第一条环境消息中重复政策，后续历史 JSON、来源角色和最后的待审查动作均保持原样。安装包不声明 DSH 版本范围限制；理论上可能适用的版本见[兼容说明](../COMPATIBILITY.md)。

重申政策是请求层兼容手段，依赖模型遵循政策，不构成确定性的语义修复，也不能证明服务后台实现。详细验证条件见 [COMPATIBILITY](../COMPATIBILITY.md)。
