# 技术实现与复核入口

[English](TECHNICAL.en.md)

[首页](../README-zh-CN.md) · [安装](../INSTALL.md) · [兼容性](../COMPATIBILITY.md)

这是独立的 DSH 插件，通过正式的 `llm/stream` 接口代理内置自动审查的模型请求。它不替换内置组件、不修改审查政策、不改变服务地址，也不执行工具。

## 做什么

- 默认不按服务或模型名称限制；这不表示已验证所有服务、模型或多模态包装。仅接管与已核对的 DSH 0.2.1-rc.3 原生审查政策指纹及请求结构均匹配的请求；不按商家或模型名称判断。普通对话、带工具的模型请求、第三方审批、标题生成和未知版本的审查均直接透传。
- 可选的 `providerIds` 是服务入口限制名单：默认空数组表示覆盖所有原生审查入口；设置名称后仅处理指定入口。模型名称始终不设白名单。无需手动编辑服务配置即可使用默认行为。
- 保留原系统提示词和全部待审数据，同时在数据末尾重申完全相同的原生审查政策与输出要求。用于兼容忽略或替换系统提示词、把审查误当成对话续写的上游。不会把待审动作交给工具执行。
- 在内存中收完每次审查返回，先检查结束状态、内容块一致性和结论，再交还内置审查。原本有效的返回保留原内容。
- 每段内容收到时保存独立副本，防止底层重复使用可变对象时覆盖先前收到的结论。
- 部分适配器会删掉思考过程最终快照的外围空白，却保留增量片段中的空白。仅当思考过程两份内容去掉外围空白后完全相同时，统一为已经收到的增量内容，同时丢弃失效的重放状态；实质内容不同仍然报错，最终结论仍要求增量和快照完全一致。
- 只处理明确包住整个结论的 Markdown JSON 代码框、外围空白及开头 BOM；不会从普通文字、DSML 工具调用、多个对象或推理过程里搜寻并拼凑结论。
- 缺失、冲突、重复字段、格式错误等会记录不含原文的错误码，然后重发同一份增强后的审查请求，默认最多重试两次（含首次共三次）。明确的合法拒绝直接交回 DSH，绝不为了取得允许而重试。
- 识别到的部分暂时性服务错误会有限重试。取消、卸载、认证失败等不重试。每次默认等待上限 60 秒，有内存和内容块数量限制。
- 成功结果仍由原来的 DSH 审查组件判断；全部尝试失败时交回失败，绝不增加工具放行例外。

## 安装和移除

使用 DSH 正常插件安装流程安装本目录或打包文件；桌面版本使用它自带的命令入口管理 `desktop` 配置。不要手工覆盖 `node_modules` 中的内置组件，不需要编辑服务配置、密钥或权限设置。

插件包自带的 `cordis.patch.yml` 只是 DSH 的标准插件挂载声明。正常安装时 DSH 会登记插件依赖和挂载信息；这不等于替换主程序或修改审批策略。

正常移除 `dsh-review-format-guard` 并重启即可退出此处理流程。移除它不会卸载内置自动审查，也不会替你切换权限模式。

## 局限

插件检查的是“接受的审查结果符合已核对的格式和字段规则”，不保证模型判断正确，也不能让有问题的上游每次都生成结论。DSML 工具调用全文不会被改写成授权结论；多次均不合格时仍会失败。

本版本不接入新的外部服务，不额外保存会话或请求原文。重试会增加上游调用次数、耗时和可能的费用。审查提示词变化后指纹不再匹配，插件会透传给内置审查，需重新核对兼容性。

源代码不含密钥，无运行时第三方依赖，没有安装后脚本。日志只包含请求序号、尝试次数、是否规范化、固定错误码，不记录结论原文或敏感信息。最终失败附带尝试次数、返回形态与字符数，方便判断插件是否重试。

## 验证

`npm test` 可独立运行，无需本机安装 DSH、无需网络或密钥。包括格式、冲突、流一致性、有限重试、取消、卸载与模型无关的入口识别测试。测试使用带有原始 MIT 许可的 0.2.1-rc.3 政策及解析器快照；它不进入安装包。

`npm run test:host` 在单独进程中使用本机 DSH 自带的真实 Cordis 和内置审查解析逻辑验证接入与撤载。它不修改 DSH 安装文件、用户配置或会话，也不调用远端模型。

设置 `DSH_EXECUTABLE` 与 `DSH_ARCHIVE` 可指定本机 DSH 程序和 app.asar 的位置。主机接入测试需要受支持的 DSH 安装，不能用快照测试替代。

模型无关表示相同的原生请求处理流程可以接入不同模型，不代表每个模型都已验证，也不能弥补模型自身的判断错误或上游拒绝服务。生图模型不适合作为文字审查模型。高风险样例必须仅作独立、虚构的审查请求，不绑定工具执行器。

## 生产代码

- [lib/index.js](../lib/index.js)：监听器、重入、重试、取消与卸载。
- [lib/protocol.js](../lib/protocol.js)：政策指纹、请求结构与结论校验。
- [lib/stream.js](../lib/stream.js)：内容块副本、完整流校验与有限规范化。

默认选项通过 `apply(ctx, options)` 传入，本版本没有图形设置面板：

```json
{
  "enabled": true,
  "providerIds": [],
  "retries": 2,
  "timeoutMs": 60000,
  "retryDelayMs": 500,
  "maxBytes": 262144,
  "maxChunks": 8192
}
```

生产插件不读取 app.asar，可选宿主验证脚本才读取安装包。政策指纹必须匹配已核对的 0.2.1-rc.3 政策。安装包不声明 DSH 版本范围限制；理论上可能适用的版本见[兼容说明](../COMPATIBILITY.md)。

重申政策是请求层兼容手段，依赖模型遵循政策，不构成确定性的语义修复，也不能证明服务后台实现。详细验证条件见 [COMPATIBILITY](../COMPATIBILITY.md)。
